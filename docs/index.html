quantize

Why TurboQuant wins.

Most KV quantizers just round the key and value tensors. TurboQuant first rotates them into a Walsh–Hadamard basis, where the energy is spread evenly across every dimension. Then it vector-quantizes. The result keeps the signal while throwing away far less information.

01 · Rotate

Apply a fast WHT to each KV vector. Rotation removes correlation bias so every component carries similar importance.

02 · Quantize

Vector-quantize in the rotated space. K stays at a coarser grain, V gets the aggressive treatment because the eye tolerates value noise.

03 · Reconstruct

Inverse WHT reconstructs the original basis. Perplexity shifts by ~1% while the cache shrinks by 4×.

The memory equation

For a model with L layers, hidden size H, and GQA grouping g, the f16 KV cache per token is:

KV(token) = 2 × L × H × (kv_heads / heads) × 2 bytes

With TurboQuant the final 2 bytes becomes ~0.44 bytes, which is where the 4.2× compression comes from. The calculator above uses the same geometry.

tune

Squeeze the last token per second.

VRAM is only half the battle. These are the knobs that actually move tokens-per-second once the model already fits.

Flash Attention

Always enable it. Flash Attention keeps the attention step memory-bound instead of compute-bound, and the larger your context the bigger the win.

GPU Layers

Use --ngl to offload every layer that fits. Even one layer left on CPU creates a cross-bus bottleneck. The TUI shows the safe maximum.

Context Right-Sizing

Don't pay for context you don't use. A 27B model at 32K needs half the KV cache of 64K, so size the window to the actual prompt.

Speculative Decoding

MTP / NextN draft heads verify several tokens in parallel. Turn it on for supported models and watch latency drop 30–50%.

Benchmark your own workload

Synthetic benches only tell you so much. Run your actual prompt through anvil and watch /stats for tokens-per-second and prompt-processing time. Then iterate on KV preset and context size until the numbers stop improving.

strike

One swing, many strikes.

anvil supports MTP and NextN speculative decoding — a draft head proposes several tokens at once, the main model verifies them in a single pass. More tokens per step, same quality.

How it works

The model's extra prediction heads guess the next few tokens cheaply. anvil feeds all of them through the main model at once — if they're right, you get them all in a single decode step.

Quality is bit-identical to normal decoding. Rejected drafts are simply discarded and re-sampled.

ANVIL(1)User CommandsANVIL(1)

NAME

anvil — forge-grade local LLM inference in your terminal

SYNOPSIS

anvil run model.gguf [--ctx N] [--ngl N]
    [--type-k T] [--type-v T] [--mtp]
    [--top-k 40] [--top-p 0.95] [--repeat-penalty 1.1]
    [--grammar f.gbnf] [-p "..."]

DESCRIPTION

anvil loads any GGUF model, auto-detects your hardware, and drops you into a streaming chat REPL. First run launches a TUI wizard; after that it just forges.

FEATURES

  • ▸TurboQuant KV cache — asymmetric K/V, 4.2× default
  • ▸MTP + NextN speculative decoding
  • ▸Flash Attention on by default
  • ▸TriAttention intelligent KV eviction
  • ▸GBNF grammars for structured output
  • ▸Hardware autodetect — CUDA · Vulkan · Metal · ROCm · CPU
  • ▸Live stats — tokens/sec, context fill, session export
  • ▸Single binary — zero telemetry, zero cloud

the-ledger

One config file. Fully yours.

Everything the wizard writes lives in ~/.anvil/config.json. Edit it by hand, version it, symlink it across machines.

// ~/.anvil/config.json { "version": 2, "ngl": 99, // GPU layers "n_ctx": 32768, // context window "n_threads": 0, // 0 = auto "temp": 0.8, "flash_attn": true, "mtp": false, // spec decode "top_k": 40, // sampling "type_k": "turbo4", // K cache "type_v": "turbo3", // V cache "model": "qwen3.6-27b.gguf" }
  • Versioned & migratedOlder configs are upgraded automatically — nothing breaks on update.
  • CLI always winsAny flag you pass overrides the file, and the file is updated to match.
  • type_k / type_v are independentMix and match any of f16, q8_0, turbo4, turbo3, turbo2 per side.
  • Sessions live alongsideExports land in ~/.anvil/sessions/ as timestamped markdown.

get-it

One line. That's the whole install.

curl -fsSL https://anvil-llm.github.io/anvil/install.sh | sh

Detects your OS + arch, grabs a pre-built binary, falls back to building from source. Installs to /usr/local/bin and creates ~/.anvil.

# clone anvil + the TurboQuant llama.cpp fork
git clone https://github.com/anvil-llm/anvil.git
git clone https://github.com/AtomicBot-ai/atomic-llama-cpp-turboquant.git llama-cpp

# build the fork
cmake -B llama-cpp/build -S llama-cpp -DCMAKE_BUILD_TYPE=Release
cmake --build llama-cpp/build -j$(nproc)

# build anvil against it
cmake -B anvil/build -S anvil -Dllama_DIR=$PWD/llama-cpp/build
cmake --build anvil/build -j$(nproc)
# Linux
cmake ≥ 3.18 · g++ / clang++ · git

# macOS (Apple Silicon runs everything on Metal)
xcode-select --install · cmake · git

# GPU backends auto-detected:
CUDA · Vulkan · Metal · ROCm · SYCL · CPU
